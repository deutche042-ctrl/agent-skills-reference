# Office Action Response Strategy

After receiving an Office Action (OA), you need to systematically analyze each ground for rejection, develop an amendment strategy, and draft a persuasive statement of arguments. This document provides a complete response methodology.

## Response Workflow

### Step 1: Comprehensively Analyze the Office Action

Read the Office Action item by item and extract the following information:

1. **Type of rejection**: Novelty, inventive step, clarity, support, sufficiency of disclosure, or something else?
2. **Claims involved**: Which claims are rejected? Independent or dependent?
3. **Cited references**: Which prior-art references did the examiner use?
4. **The examiner's reasoning**: What does the examiner believe the references disclose? Where does the examiner think the differences lie? Why does the examiner think the differences are obvious?

Organize each objection into a structured table:

```
| No. | Claims involved | Type of rejection | References | Summary of examiner's view |
|------|-------------|---------|---------|--------------|
| 1    | Claims 1-5  | Inventive step | D1+D2 | D1 discloses ..., D2 discloses ..., and their combination is obvious |
| 2    | Claims 6-8  | Clarity | -       | The meaning of "processing" is unclear |
```

### Step 2: Assess the Reasonableness of Each Objection

Make an independent judgment on each objection:

- **Is the examiner's understanding correct?** Did the examiner correctly understand the technical solution of the claim? Sometimes the examiner's misunderstanding is itself the breakthrough point for the response.
- **Is the citation of the reference appropriate?** Does the reference really disclose the feature the examiner claims? Is there any misinterpretation?
- **Does the logic hold up?** Especially in inventive-step rejections, is the "motivation to combine" adequate?

### Step 3: Develop a Response Plan

For each objection, decide which of the following strategies to use (or a combination):

| Strategy | Applicable scenario |
|---|---|
| **Argue** (do not amend the claim; argue that the examiner's judgment is wrong) | The examiner clearly misunderstood the technical solution or the reference |
| **Narrow** (add limiting features to the claim) | The current independent claim indeed differs little from the reference, but the dependent claims contain a distinguishing feature |
| **Delete** (delete the rejected claim) | The claim is unimportant to the protection strategy |
| **Merge** (incorporate a dependent-claim feature into the independent claim) | A feature in the dependent claim happens to constitute a substantive difference from the reference |
| **Rewrite** (rewrite the wording of the claim) | Clarity problems, improper expression |

### Step 4: Execute the Amendments and Draft the Statement of Arguments

First amend the claims and the specification (if needed), then draft the statement of arguments justifying that the amended solution meets the conditions for grant.

## Responding to Novelty Rejections

A novelty rejection means the examiner believes that a single reference has already disclosed all the technical features of the claim.

### Analysis Method

Compare each technical feature in the claim one by one against the content disclosed in the reference:

```
| Technical feature | Disclosed in the reference? | Analysis |
|---------|----------------|------|
| Feature A | Yes | Paragraph X of D1 discloses ... |
| Feature B | Yes | FIG. X of D1 shows ... |
| Feature C | No / partly | The XX of D1 differs from the XX of the present application as follows: ... |
```

### Response Approach

1. **Find a distinguishing feature**: Compare carefully and find at least one technical feature that the reference does not disclose (or discloses differently). Novelty follows the "complete coverage" principle—as long as one feature is different, novelty is established.

2. **Whether the reference really discloses that feature**: The examiner sometimes reads the reference too broadly. Check the original text of the reference to see whether it really explicitly discloses what the examiner alleges. If the reference merely "implies" or "mentions in passing", you can argue that it is not an "explicit disclosure".

3. **Difference in the connotation of the technical feature**: Even if the surface wording is similar, if the technical connotation differs (e.g., "processing" has different meanings in different contexts), you can argue the difference from the level of technical essence.

4. **If there really is no difference**: Incorporate a distinguishing feature from the dependent claims into the independent claim, narrowing the scope of protection to overcome the novelty problem.

## Responding to Inventive-Step Rejections

Inventive-step rejections are the most common and most complex type of rejection. Examiners usually use the "three-step approach" to judge inventive step:
1. Determine the closest prior art
2. Determine the distinguishing features and the technical problem actually solved
3. Judge whether the distinguishing features are obvious to a person skilled in the art

The response also unfolds around these three steps.

### Strategy 1: Challenge the "Closest Prior Art"

- Is the reference selected by the examiner really the "closest"?
- If the technical field to which the reference belongs differs greatly from that of the present application, you can question its reasonableness as the closest prior art

### Strategy 2: Redefine the Distinguishing Features

- Did the examiner overlook certain distinguishing features?
- Did the examiner split up multiple features of the claim and find their counterparts separately in different references? If so, check whether there is a synergistic relationship among these features—the effect produced by the whole combination is not the simple sum of the parts

### Strategy 3: Argue That the "Motivation to Combine" Does Not Exist

This is the most powerful line of argument in an inventive-step response. The examiner must prove that two references "can be combined", whereas you argue that "there is no reason to combine them":

- **Difference in technical field**: Do the two references belong to different technical fields? Combining technical solutions from different fields requires a stronger motivation to combine
- **Difference in technical problem**: Do the two references each aim to solve the same technical problem? If not, what is the motivation to combine them?
- **Difference in function/role**: Is the role of the distinguishing feature in the reference the same as its role in the present application? If not, the "teaching" does not hold
- **Technical contradiction**: Do the solutions of the two references conflict? Would combining them destroy the technical effect of one of them?
- **Teaching away**: Does the reference explicitly suggest a direction opposite to that of the present application?

### Strategy 4: Emphasize Unexpected Technical Effects

If the technical solution of the present application produces an unexpected technical effect (not a simple additive effect of the prior art), this is strong evidence of inventive step:

- Does the effect exceed the expectation of a person skilled in the art?
- Is the effect not a simple sum of the individual features' effects, but rather a synergistic effect?
- Is there experimental data or comparative data to support it?

### Strategy 5: Narrow the Claim

If the above strategies all struggle to persuade the examiner, consider incorporating a feature from the dependent claims into the independent claim:

- Which dependent-claim feature to incorporate? Choose the one that best constitutes a substantive difference from the reference
- Is there still sufficient scope of protection after incorporation? Assess the commercial value
- Is the incorporated feature sufficiently supported in the specification?

## Responding to Clarity and Support Rejections

### Clarity Problems

The examiner believes the wording of the claim is unclear and the scope of protection is indefinite.

**Common causes and countermeasures**:

| Problem pointed out by the examiner | Countermeasure |
|---|---|
| Unclear meaning of a term | Replace with a more definite technical term, or add a defining limitation in the claim |
| Unclear scope of protection | Further limit the technical features to remove ambiguity |
| Missing antecedent basis | Supply the antecedent basis, ensuring every "the said" has a corresponding introduction |
| Grammatical ambiguity | Rewrite the sentence to eliminate the possibility of multiple interpretations |

### Support Problems

The examiner believes the scope of protection of the claim exceeds the content disclosed in the specification.

**Common causes and countermeasures**:

| Problem pointed out by the examiner | Countermeasure |
|---|---|
| Over-broad generalization | Supplement more lower-level (specific) embodiments in the specification, or narrow the claim appropriately |
| Functional limitation without support | Supplement in the specification the specific structure/method for implementing that function |
| Effect not verified | Supplement experimental data or theoretical analysis in the specification (taking care not to exceed the scope) |

## Claim Amendment Strategy

When amending claims, comply with the "no addition of new matter" principle: the amended content must be within the scope recorded in the originally filed application documents.

### Overview of Amendment Approaches

| Amendment approach | Operation | Effect | Risk |
|---|---|---|---|
| Narrow | Incorporate a dependent-claim feature into the independent claim | Reduces the scope of protection but overcomes the rejection | The scope of protection may become too narrow |
| Delete | Delete a claim | Gives up that protection | One fewer line of defense |
| Merge | Merge the features of multiple claims | Forms a new protection combination | Must ensure the combination has a basis in the original text |
| Rewrite | Change the wording without changing the technical solution | Eliminates formal problems | May be seen as changing the scope of protection |

### Prioritizing Amendment Decisions

When you need to narrow the independent claim, how to choose which dependent-claim feature to incorporate:

1. **Greatest degree of difference**: Choose the feature that differs most clearly from the reference; it is most likely to overcome the rejection
2. **Highest commercial value**: Choose the feature that competitors are most likely to implement, so the scope of protection has the most commercial significance
3. **Best-supported evidence**: Choose the feature with the most detailed description and effect justification in the specification
4. **Comprehensive judgment**: Strike a balance among the above three

## Framework for Drafting the Statement of Arguments

The statement of arguments is the core document for persuading the examiner. A clear structure and strong reasoning are key.

### Basic Framework

```
## Statement of Arguments

### I. Explanation of Amendments
[Briefly explain what amendments were made to the claims/specification and the basis for the amendments]

Amendment content:
- Claim 1: incorporated the feature of the original dependent claim X, adding the limitation "..."
- Claims Y-Z: due to the amendment of the independent claim, the reference relationships of the dependent claims were adjusted accordingly
- [Other amendments]

Basis for amendments: All of the above amendments are recorded in paragraph X of the original specification / original claim X, and do not exceed the scope recorded in the originally filed application documents.

### II. Comments on Novelty/Inventive Step

#### 2.1 Comparison of amended claim 1 with reference D1

[Feature-by-feature comparison, clearly identifying the distinguishing features]

#### 2.2 Analysis of the distinguishing features

[Argue why the distinguishing features are not obvious—use a specific strategy from "Responding to Inventive-Step Rejections" above]

#### 2.3 Technical effects

[Argue the technical effects produced by the amended technical solution]

### III. Responses to Other Objections

[Respond to the other problems item by item]

### IV. Conclusion

In summary, the applicant submits that the amended claims [outline the reasons], and respectfully requests the examiner to approve the grant.
```

### Drafting Key Points

1. **Respond to every objection item by item**, omitting none. Even if an objection has been naturally overcome by the amendment, state so explicitly.

2. **The argument must contain specific technical analysis**; do not merely say "the difference is obvious" or "it is not obvious"—make clear why.

3. **Cite the original text accurately**: cite the specific paragraphs and figure numbers of the reference, and cite the specific paragraphs of the present application's specification.

4. **Keep the tone professional but firm**. Do not shrink from well-founded arguments, but also do not use derogatory wording toward the examiner's views.

5. **Amending and arguing can proceed in parallel**. For example: first narrow the claim to ensure at least a grant, while at the same time raising arguments on the inventive-step objection to the original independent claim—if the argument succeeds, the broader scope of protection can be restored.

## Formatted Document Output

If the user provides the original application document in .docx format, amend it directly using the replace mode with tracked changes enabled:

```bash
uv run ../scripts/docx_edit.py replace original_claims.docx amended.docx replacements.json
```

Set `"track_changes": true` in `replacements.json` so the examiner can see what was changed.

The statement of arguments is usually a new file; generate it using the create mode.

Setting `"track_changes": true` allows changes to be marked with revision marks. Run `uv run ../scripts/docx_edit.py --help` to view detailed usage.
